btrfs Filesystems (mounted + unmounted)
Scanning...
Unmounted filesystems show profiles as unknown and no error counters - those need a mount. Locked-LUKS members stay invisible until unlocked on the Data Disk page. Each member is shown with the physical disk that holds it (serial, model, transport) - that is how two identical disks are told apart when one of them has to be replaced. Any non-zero error counter (w/r/f/c/g) deserves attention. Several profiles per type (e.g. single+RAID1) mean part of the data has no mirror - Balance converts the rest to RAID1. A member that reports unused space is a disk larger than the size btrfs registered when it joined; that surplus has no mirror partner and therefore cannot raise the capacity of a two-disk RAID1. Scrub, balance, add, remove and replace are kernel operations and only work on mounted filesystems - that is a btrfs requirement, not a UI limitation.
Replace a Disk
Online replace - filesystem stays mounted. May take hours. Offered as replacement are unused disks and prepared LUKS members (see below). The member list shows the physical disk (serial, model) behind each mapper. A disk that is already gone is listed by its devid ("missing") - that is exactly the source a replace rebuilds from the surviving mirror.

Scrub
Starting a scrub records its result for the health check when it finishes - a successful run also clears an "aborted" entry, so the monthly scan resumes. A scrub only reads data and verifies it against the RAID1 mirror copy; it repairs nothing by itself, but it makes a silent bit rot visible (and fixes it when a good copy exists).
